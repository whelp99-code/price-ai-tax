# price · AI 세무사 — 자료 업로드만으로 사용하는 대표용 제품 요구사항

기준: 2026-09-28 사용자 직접 정정. 이 문서는 기존 개발계획의 사용자 경험·우선순위·제품 인수 조건을 교정한다. 기능 구현 완료 보고서가 아니다.

## 1. 변경할 수 없는 목표

사용자는 세무·회계를 모른다. 통장내역, 세금계산서, 카드내역 등 원본 파일을 올리면 앱이 자료 읽기·거래 연결·기장·검증·세금 계산·신고 준비·결과 설명을 주도해야 한다. 회사 업무의 사실만 필요한 경우 짧고 쉬운 질문으로 확인한다. 목표는 독립 AI 세무사이며 가격비교 앱이나 전문가에게 자료만 전달하는 시스템으로 축소하지 않는다.

대표가 알아야 하는 일은 자료 제출, 본인만 아는 사실 답변, 중요한 선택 및 실제 대외 실행 확인이다. 계정과목, 차변·대변, 과세구분, 공제 여부, 세무조정, 신고서 항목을 사용자가 직접 판단하는 방식은 제품 성공이 아니다. 같은 사람이 demo-owner와 demo-reviewer를 번갈아 사용하는 방법을 실사용 흐름으로 권하지 않는다.

## 2. 현재 코드에서 확인한 격차

- price/api.py의 POST /evidence는 Service.upload_evidence만 호출한다. 업로드 완료가 자동 거래 입력·분석 완료가 아니다.
- POST /imports/csv, /transactions, /transactions/{id}/analyze가 별도 사용자 작업으로 분리돼 있다.
- price/static/app.js의 upload 동작은 원본 보관을 수행한다. 대표가 별도로 거래·분석 메뉴를 다뤄야 하는 구조다.
- 현재 docs/IMPLEMENTATION_STATUS_KO.md는 PDF·이미지 추출/OCR 미연결, 금융자료 수집 미연결, 실제 LLM 판단 품질 미검증, 법정 완전 세목 계산 미완성을 명시한다.
- 기존 자동시험과 HTTP·브라우저 시험은 기술적 기반의 시험이다. 회계 지식 없는 사용자에게 업무를 완수시킨다는 제품 인수 시험이 아니다.

현재 장부·승인·감사·격리 코어는 보존한다. 잘못된 대상 사용자를 위한 전면 화면과 수집·자동처리 연결을 수정한다. 사용자 데이터나 확정전표를 초기화하지 않는다.

## 3. 대표용 화면: 세 가지 업무만

### 자료 올리기
통장내역·세금계산서·카드내역·영수증·계약서 등 여러 파일을 함께 제출한다. 지원하는 파일의 종류와 항목은 앱이 자동으로 인식한다. 앱 전용 CSV 작성이나 열 이름 변경을 정상 사용 절차로 요구하지 않는다. 원본은 그대로 보존하며 암호화된 문서, 읽지 못한 양식, 손상 파일은 실패를 감추지 않는다.

### 답변이 필요한 것
실제 거래의 날짜·상대방·금액과 해당 질문의 이유를 보여준다. '회사 업무인가요 / 개인 사용인가요 / 모르겠어요', '고객 납품용인가요 / 회사에서 사용하는 장비인가요', '고객이 보낸 대금인가요 / 대표가 넣은 돈인가요 / 다른 사유인가요'처럼 사실을 묻는다. 질문은 기존 자료 탐색 후 최소화하고, 여러 자료에 공통으로 필요한 사실은 한 번만 묻는다. '모르겠어요'는 잘못된 답변이 아니며 내부 검토 경로로 넘긴다.

### 결과 보기
들어온 돈·나간 돈과 회계상 매출·비용을 구분해 쉬운 말로 보여준다. 자료 처리 상태, 예상 또는 확정 세금, 필요한 추가 자료, 해야 할 결정만 기본 화면에 둔다. 관련 자료·계산·원장은 상세 보기와 전문가 작업 화면에 남겨 추적 가능성을 유지한다. 예상값을 확정값으로 표시하지 않는다.

## 4. 첫 사용과 자료 부족

사업자등록증 등 이미 있는 파일에서 회사 정보 후보를 읽고 법인·사업장·회사 소유 계좌·카드를 확인한다. 앱이 찾을 수 없는 회사의 사업 내용과 문서상 불일치만 질문한다. 인증정보를 일반 대화나 기억 저장소에 넣지 않는다.

올린 자료가 전부라는 사실만으로 과거 잔액·자산·채무가 완전하다고 가정하지 않는다. 처음 장부를 시작할 때 필요한 기존 장부·이전 신고자료가 있으면 어떤 자료가 왜 필요한지 쉬운 말로 안내한다. '기초대차를 맞추라'고 대표에게 회계 작업을 지시하지 않는다. 처음 제출한 자료만으로 해결되지 않는 항목은 정확한 남은 일로 관리한다.

## 5. 업로드 이후 실제 처리 계약

1. 원본 보관, 접근권한, 해시, 파일별 처리 ID를 생성한다.
2. 파일 유형·출처·계좌 또는 카드 식별·기간·시트·거래 행을 읽는다. 읽지 못한 행은 누락하지 않는다.
3. 원문 금액·날짜·합계·통화·입출금 방향·취소·수정 여부를 결정론적으로 검사한다. 원본과 추출 결과를 비교 가능하게 보존한다.
4. 출처별 기록을 하나의 경제적 거래에 연결한다. 세금계산서, 카드 결제, 계좌 출금이 같은 거래를 설명할 수 있음을 처리한다. 날짜와 금액만 같은 정상 거래를 무조건 합치지 않는다.
5. 자료·회사 사실·승인된 정책으로 거래 목적을 추론한다. 근거가 부족할 때만 사실 질문을 만든다.
6. 분개와 세무 처리안을 생성하고 독립 검증한다. 계산은 프로그램이 수행하며 LLM이 금액을 임의 확정하지 않는다.
7. 사전 승인된 좁은 자동처리 정책과 검증을 통과한 거래군만 자동확정 대상으로 삼는다. 현재의 승인 통제를 삭제하거나 가짜 검토자 계정으로 우회하지 않는다. 정책·검증·승인 구조의 변경은 별도 구현과 시험을 거친다.
8. 미해결 항목을 제외해 성공률을 높여 보이지 않는다. 자동 완료, 사실 질문, 내부 전문 검토, 자료 추출 실패, 미지원, 실제 제출 대기를 구별한다.
9. 답변이나 추가 자료가 도착하면 해당 사건만 재개한다. 이미 끝난 거래를 중복 기장하지 않는다.
10. 장부·대사·마감·계산·신고 준비·결과 보고를 연속 업무로 관리한다. 실제 신고·납부·송금은 각 행위에 필요한 승인·권한·실제 결과 확인을 별도로 유지한다.

## 6. 반드시 자동화할 연결 사례

- 하나의 장비 매입을 설명하는 세금계산서와 계좌이체를 중복 비용으로 기록하지 않는다.
- 카드 사용내역과 통장에 나타난 카드대금 결제를 새로운 두 지출로 중복 비용 처리하지 않는다.
- 계좌 사이의 이체, 대표 입금, 대출 등과 고객 매출대금을 구분한다. 문서에 없는 사실을 만들어 분류하지 않는다.
- 부분 입금·분할 결제·합산 입금을 처리하고 미수·미지급을 설명한다.
- 카드 취소·환불·수정세금계산서는 원거래와 연결하고 이전 승인·신고에 미치는 영향을 관리한다.
- 자동 비교가 여러 후보 사이에서 모호하면 강제로 하나를 고르지 않는다.
- 자료에 부가세가 없다는 이유로 임의 세액을 생성하지 않는다. 세법 규칙과 실제 증빙·요건의 판정이 필요하다.

## 7. 질문과 전문 검토의 경계

대표에게 묻는 것은 회사 업무의 사실과 선택이다. 세무 판단을 사용자에게 묻지 않는다. '매입세액 공제 가능한가요?' 대신 필요한 업무 목적·사용자·증빙 사실을 확인한 후 앱이 판정한다.

독립 검증은 유지하되 대표가 두 계정으로 자신을 검토하는 방식을 제시하지 않는다. 검증된 반복 업무는 자동 정책으로, 복잡한 세무 판단은 내부 전문 검토 사건으로 분리한다. 전문가가 아직 연결되지 않은 검토는 '검토 연결 필요'로 표시하며 검토 중이라고 위장하지 않는다. 대표의 세무 지식 부족을 오류 해결 방법으로 삼지 않는다.

## 8. 개발 순서

| ID | 범위 | 완료 증거 |
|---|---|---|
| UF-01 | 대표용 홈·자료 업로드·쉬운 질문·결과 보기 | 회계 메뉴와 계정 전환 없이 대표 과업 수행 |
| UF-02 | 실제 파일 양식 파서·원본/행/합계 추적·암호/실패 처리 | 출처별 파일 fixture와 전체 행·금액 대조, 추출 실패 노출 |
| UF-03 | 업로드→영속 수집→검증→거래 등록→자동분석 연결 | 업로드만으로 작업 생성·진행·재시작·취소·중복 없는 재개 |
| UF-04 | 세금계산서·통장·카드의 교차 연결 | 혼합 제출·제출 순서 변경·중복·카드대금·내부이체 사례 통과 |
| UF-05 | 자연어 사실 질문·질문 묶음·답변 후 재개 | 세무 용어 입력 없이 해결, 모름 답변의 검토 전환 |
| UF-06 | 검증된 자동기장 정책·독립 검증 | 승인 경계·범위·원본 일치·오류 비용·오확정 회귀 검증 |
| UF-07 | 마감·세금·신고 준비 자동 연결 | 미해결·비지원·추정 표시, 실제 접수·납부 별도 확인 |
| UF-08 | 회계 비전문가 실사용 인수 시험 | 업로드 후 질문 최소화, 수기 거래 입력 0, 전문가 계정 전환 0 |

기존 세목 전체 구현, 법정 규칙과 공식 신고서 개발도 최종 AI 세무사 범위에서 유지한다. 화면 개편만으로 전체 제품을 완료했다고 하지 않는다. 실제 금융·홈택스 자동수집은 이후 업로드 부담을 더 줄이는 확장이며, 먼저 파일 제출 흐름을 완성한다.

## 9. 새 제품 인수 조건

- 지원 범위의 통장·세금계산서·카드 원본 묶음을 그대로 올렸을 때 종류 선택·열 매핑·거래 수기 입력 없이 처리된다.
- 동일 파일 재업로드와 서로 다른 출처의 동일 경제적 거래 때문에 비용·매출이 중복되지 않는다.
- 사용자 질문에는 날짜·금액·상대방·부족한 사실·모르겠어요 경로가 있다. 계정과목·공제 여부를 묻지 않는다.
- 대표는 회계 용어를 입력하지 않고 검토자 계정으로 바꾸지 않아도 자신의 할 일을 마칠 수 있다.
- 미해결 세무 검토는 대표의 숙제로 떠넘기지 않되 대기 상태와 책임자는 정확히 공개한다.
- 처리 완료에는 원본 합계 대조, 추적성, 실제 처리 결과가 필요하다. 파일 저장 성공과 작업 큐 등록 성공은 업무 완료가 아니다.
- 계산된 매출·비용과 통장 입출금을 구분하고 추정·검증완료·실제 신고·납부 상태를 섞지 않는다.
- 실자료는 사용자 승인과 접근통제 아래만 이용한다. fixture/데모 결과를 실제 자료 검증처럼 제시하지 않는다.

## 10. 이번 정정 작업의 상태

프로젝트 규칙, 구현상태, API와 업로드 동작을 읽고 사용자 목표와 어긋난 지점을 확인했다. 본 문서는 제품 목표·우선순위·인수 기준을 반영한 요구사항이다. 이번 문서 작성만으로 UI, 파일 파서, 자동기장 기능을 구현·검증·배포했다고 표시하지 않는다. 실제 세무신고·납부·송금, 커밋·푸시, 원본 데이터 변경은 수행하지 않는다.
