# price · V01 개발 루프 실제 상태

기준: 2026-09-28. 독립 작업 경로 `/home/jm/orca/projects/price`. 제품은 AI 세무사이며 가격비교가 아니다.

## 현재 판정

**V01: 구현 진전 / 인수 미완료. V02~V10: 다음 버전으로 승인하지 않음. 최종 1.0.0: 미완료.**

대표용 업로드 화면과 실제 원본 읽기 경로를 구현했다. 실제로 통과한 시험과 아직 남은 결함·실자료 인수 조건을 아래에 분리한다. 테스트를 삭제하거나 모의 증거를 실제 기관 검증으로 바꿔 버전을 완료 처리하지 않는다.

## 개발 → 검증 → 수정 → 재검증 기록

1. 기존 회귀시험 179개를 재실행해 모두 통과했다. 소스 43개와 기존 DB 1개의 프로젝트 로컬 체크포인트를 만들고 DB 무결성을 확인했다.
2. `ingest_safety.py`, `uploads.py`에 파일 구조·크기·압축·XML 검증, 1MB 청크 전송/재개/해시, 배치 멱등성, 원본 보존, 영속 읽기 outbox를 구현했다. 안전 검사 28개와 업로드 저장소 19개 시험을 통과했다.
3. `source_tables.py`, `ingestion.py`에 원본 한글 CSV/TSV 자동 분류, 금액·일자·합계·행/열 추적, 원문 후보 저장, 별도 거래 확인 사건 생성, lease/fencing/권한 재검사를 구현했다. 해당 시험 35개를 통과했다.
4. `owner.py`, `upload_routes.py`, `static/owner.*`를 기존 API/worker에 연결했다. 대표 기본 화면은 자료 올리기·답변이 필요한 것·결과 보기 세 영역이다. 기존 전문가 기능은 `/expert`에 보존했다. Origin/CSRF/회사 격리/독립 승인 검사는 제거하지 않았다.
5. 회사 소유 계좌·사업자가 다른 원본의 잘못된 승격 2건을 새 실패시험으로 재현한 뒤 수정했다. 이후 원본 읽기/API 52개를 통과했다.
6. 실제 별도 Chrome/API/worker 환경에서 초기 대표 과업 16개와 기존 전문가 과업 22개를 통과했다. 실제 파일 선택, 여러 파일 제출, API 재시작 뒤 outbox 재개, 같은 자료 재제출, 비신뢰 HTML 비실행, 계정 전환 없는 회사 사실 확인, 모바일 390px을 시험했다.
7. `source_workbooks.py`와 `native_documents.py`를 추가했다. XLSX 저장값/공유문자열/1900·1904 날짜/셀 원문을 읽되 수식을 실행하지 않는다. 텍스트형 사업자등록증에서 회사 정보 후보를 읽고 대표에게 사실 확인을 요청한다. 일반 PDF 표, 스캔 이미지, 암호 문서, 구형 XLS, 세금계산서 XML의 전체 항목 인식은 아직 완료가 아니다.
8. 회사 사실이 나중에 확인될 때의 충돌 3건을 추가 재현하고 `source_identity.py`로 수정했다. 원본과 확정 장부는 변경하지 않고 잘못 승격된 자료/연결 후보를 다시 보류한다. 수정 후 전체 회귀 314개를 통과했다.
9. 확장 실제 브라우저 과업 17개를 통과했다. CSV, XLSX 컨테이너, Chrome으로 생성한 한국어 텍스트 PDF를 함께 올리고 PDF에서 회사 정보가 자동 제시되는 것을 확인했다. 모든 자료는 합성 시험자료다.
10. 기존 `scripts/runtime.py start`에서 API 또는 worker 하나만 살아 있으면 나머지를 복구하지 않는 두 경로를 새 시험으로 재현했다. 이 결함의 수정 파일 생성 요청은 동일한 정상 요청으로 재확인해도 보안 판정에서 두 번 차단됐다. 수정은 적용되지 않았고 실패시험을 그대로 보존했다.

## 미해결 결함

- `test_start_repairs_missing_worker_without_replacing_api`: API 생존 / worker 종료 시 start가 worker를 복구하지 않는다.
- `test_start_repairs_missing_api_without_replacing_worker`: worker 생존 / API 종료 시 start가 API를 복구하지 않는다.
- 수정 대상은 프로젝트 로컬 supervisor의 부분 재시작이다. 다른 프로젝트나 시스템 서비스 변경이 아니다. 실패 원인을 숨기기 위해 시험을 삭제하지 않는다.

## 버전 인수 조건

V01의 실제 기관 원본 양식 묶음 대조, 회사 사용 양식 목록 확정, 남은 복구 결함 수정, 회귀/브라우저/복원 재검증이 필요하다. CSV/XLSX/PDF라는 실제 파일 컨테이너를 시험한 사실과 은행·카드사·홈택스에서 내려받은 실제 양식을 검증한 사실은 다르다. 현재 지원표의 `accepted_institution_formats`는 빈 목록이다.

V02의 스캔/OCR·미지 양식·전체 문서 처리, V03 교차 거래 연결, V04 실제 모델과 업무 사실 질문, V05 승인 정책 자동기장, V06 월마감, V07/V08 완전 세목, V09 실채널, V10 운영 인수는 완료되지 않았다. 준비된 코드 일부를 근거로 다음 버전을 자동 승인하지 않는다.

## 구현 경계와 사용상태

- 원본 읽기와 장부/세무 업무 완료는 별도다. 신규 대표 화면은 이를 명시한다.
- 작성자 자기 승인 금지와 기존 원장 불변·역분개 경로를 보존했다.
- native PDF 읽기는 자원 제한이 있는 별도 Poppler 프로세스다. 이것을 백신 인증 또는 모든 공격에 대한 보장으로 표현하지 않는다.
- 기존 원본과 DB, 다른 프로젝트를 삭제·초기화하지 않았다.
- 실제 홈택스·금융·신고·납부 요청, 커밋·푸시, 공개 포트, systemd 설치, Orca worker 등록은 수행하지 않았다.
- 개발 진행용 loop 도구 기록은 지속 실행되는 자율 개발 프로세스가 아니다.
