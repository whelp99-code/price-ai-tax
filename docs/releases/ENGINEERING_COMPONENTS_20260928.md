# price · V01~V10 개발계획에 대한 실제 구현 스냅샷

**판정: 개발·검증 스냅샷이며 V10 최종 인수 완료가 아니다.** 제품/worker는 price, 작업 경계는 `/home/jm/orca/projects/price`다. 현재 패키지의 기준 버전은 0.2.1을 유지한다. 파일과 시험의 존재를 근거로 1.0.0 또는 각 버전의 ACCEPTED 상태를 만들지 않는다.

## 1. 이번 작업의 출발 상태

다시 연결한 시점의 전체 시험은 351개 통과였다. 이전에 보고된 runtime 부분복구 실패 2건은 현재 체크아웃에서 이미 수정되어 통과했다. 해당 기존 수정과 다른 작업의 원본 파서·재처리 개선을 보존했다. 현재 소스 80개 및 기존 DB 1개의 프로젝트 내부 체크포인트를 만든 뒤 후속 구현을 진행했다. 공유 작업 트리의 다른 변경을 자신의 단독 작업으로 주장하지 않는다.

현재 전체 시험 결과는 `evidence/version-loop/cross-version-regression.xml`에 저장된다. 이 문서 작성 직전 실행에서는 **501 PASS, 0 FAIL, 0 ERROR, 0 SKIP**, 프레임워크 사용중단 경고 2건이었다. 이후 별도 검증 스냅샷에 실행 시점과 코드 해시를 함께 저장한다.

## 2. 사용자에게 실제로 연결한 흐름

1. 통장·카드·세금계산서·사업자등록증 원본을 대표 화면에서 제출한다.
2. 영속 읽기 worker가 원본 위치·금액·기간·합계를 검증하고 자료 기록을 만든다.
3. 경제적 거래를 생성하되 파일/출처 레코드/실제 거래 식별을 구분한다. 참조가 없는 같은 금액의 정상 두 거래를 삭제하지 않는다.
4. 청구 참조번호·상대 사업자·방향·통화가 모두 일치하는 유일한 결제 관계만 자동 연결한다. 부분결제의 양쪽 금액을 보존한다. 금액만 맞는 후보는 확정하지 않는다.
5. 대표에게 업무 사용 여부와 사용 목적만 묻는다. 세무 공제·계정과목을 묻지 않는다. 답변을 저장하면 다음 질문이 자동으로 이어진다.
6. 원본의 명시 참조로 결제가 이미 설명되면 입출금 이유를 다시 묻지 않는다.
7. '모르겠어요'는 실제 UNASSIGNED 검토 사건을 만들고 담당자 연결 필요로 남긴다. 등록된 검토자가 배정·수락했을 때에만 그 상태가 대표 화면에 반영된다.
8. 검토된 좁은 자동기장 정책의 평가·실행 허가와 단일 원장 효과를 구현했다. **기본 HTTP/운영 경로의 자동기장 실행은 아직 활성화하지 않았다.** 격리 시험에서는 실행 서비스에 명시적으로 허용해 실제 SQLite 전표 생성·불변·중복 방지를 검증했다.

위 흐름은 합성 자료로 실제 브라우저와 API/worker를 통해 시험했다. 실제 금융기관의 모든 양식이나 실제 회사의 전문 세무 정답을 검증했다는 의미가 아니다.

## 4. 중요한 수정·검증

- 경제사건의 컨텍스트 해시 생성과 재검증에서 포함 필드가 달랐던 결함을 수정하고 전량 회귀를 통과했다.
- 마스킹된 카드번호를 강한 전역 식별자로 사용하지 않는다. 같은 금액의 정상 반복행은 보존한다.
- 사실 답변에는 질문 컨텍스트와 사실 revision을 함께 검사한다. 두 답변이 동시에 들어오면 낡은 값이 새 값을 조용히 덮어쓰지 못한다.
- 원본 재추출·회사 정보·업무 사실이 바뀌면 과거 사실 질문, 결제 배분, 정책 허가, 전문 검토, 신고 스냅샷을 재확인한다.
- 실제 원본에서 충분히 증명된 입출금 목적은 사용자에게 다시 질문하지 않는다.
- 원본 조회는 한 요청 안에서 동일한 스냅샷을 공유하고, 사실/출처/결제 조회 인덱스를 추가했다. 부하 한계 전체 인수를 했다는 뜻은 아니다.
- 전문 검토 계정이 배정돼도 수락 전에는 '검토 중'이 아니다. 계정 권한 철회 후 담당 상태를 갱신한다. 앱의 reviewer 역할을 세무 자격 검증으로 간주하지 않는다.
- 업로드 자료를 원장에 반영하지 않은 채 기존 수기 수집완료 표시만으로 월마감할 수 없도록 보강했다.
- 원본 업로드가 승인된 모의 신고 뒤 들어오면 기존 계산 해시가 달라져 다시 검토하도록 한다.
- 제출 채널이 없으면 실제 제출 시도도 생기지 않는다. 모의 응답은 SIM_RECEIVED이며 납부 완료로 바뀌지 않는다. 접수 후 통신 장애는 결과 조회 전 재전송하지 않는다.
- 인수 결과는 독립 검토자, 현재 코드, 실제 증거 종류, 중요 시험 실패, 관찰기간 등을 검사한다. 실제로 존재하지 않는 인수 증거를 생성하지 않았다.

## 7. 확인된 외부 조건

현재 price의 실제 모델 설정은 없었다. 조회한 localhost Ollama 모델 서버도 연결되지 않았다. 다른 프로젝트의 비밀정보를 가져오거나 유료 호출·대규모 모델 다운로드를 임의 실행하지 않았다.

## 8. 배포와 증거

기본 앱은 loopback 검증 모드이며 외부 신고·납부가 비활성이다. 정확한 현재 프로세스 상태는 `python3 scripts/runtime.py status`로 확인한다. 서비스 재부팅 자동시작과 Orca 등록은 별도 인수 대상으로 남긴다.

회귀 XML, 실제 대표 과업·기존 전문가 과업·HTTP 보고서, 코드 스냅샷과 패키지 해시를 함께 보존한다. 예전 315/317 보고서를 현재 상태로 재사용하지 않는다. 'goal_loop' 기록은 실행 중인 별도 자율 개발 프로세스가 아니다.

## 9. 마지막 재검증·패키지·가동 확인

2026-09-28 14:33:24 UTC의 검증 스냅샷에서 시험 전후 소스 해시가 같았고, 전체 501개 회귀가 통과했다. 같은 코드로 실제 HTTP 21개, 대표 원본 제출 브라우저 17개, 업무 사실/결제 연결 브라우저 14개, 기존 전문가 브라우저 22개, 원본 재처리 브라우저 23개를 각각 통과했다. 숫자는 서로 중복될 수 있는 검증 항목 수이며 세무 업무의 완성도나 실자료 정확도 비율이 아니다.

소스 120개 파일을 데이터 없는 개발 ZIP으로 만들고 파일별 해시를 검증했다. 별도 디렉터리에 풀어 실제 패키지 import·새 DB 스키마·대표/전문가 정적 화면·인증된 API를 확인했다. pip 설치 시험이라고 표시하지 않는다. ZIP 이름은 `artifacts/price-development-*.zip`이며 해당 JSON에 해시와 시험 스냅샷 참조가 있다.

기존 DB를 다시 백업한 뒤 소유권이 확인된 price API와 worker만 재시작했다. 새 프로세스 API 4064103 / worker 4064145, loopback 4381, health 정상과 새 API 명세의 경로 존재를 확인했다. 인증된 운영 DB 프로브는 도구 안전 검사에서 차단되어 실행하지 않았고, 별도 합성 DB의 인증·업무 과업 시험과 구분했다. 이를 인증된 운영 데이터 종단 검증 완료라고 보고하지 않는다. 실제 신고·납부·공개 서비스·Orca 등록은 여전히 미실행이다.
